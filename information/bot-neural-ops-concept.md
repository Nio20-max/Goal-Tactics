# Bot Neural Ops Concept

## Goals

1. Keep deterministic real-time action execution in C#.
2. Use the local neural model to decide bot intent/persona/plans, especially at night.
3. Give each bot group its own chat channel (stored in bot DB) for transfer coordination.
4. Keep the model loaded in RAM and exposed via local HTTP API.
5. Support concurrent bot requests, but with strict limits.

## Current baseline

- Bots run in `bots/` with behavior modules (daily, lineup, training, transfer, social, stadium, skill cards).
- Personality is static (`Activity`, `Risk`, `YouthFocus`, `SocialScore`), generated once at registration.
- Groups exist in SQLite (`Bots.GroupId`, `BotGroups`) but group chat is not persisted yet.
- Chat endpoint is global (`PostChatMessage`) and not group-scoped server-side.
- LFM2.5 model asset exists at `models/lfm25/LFM2.5-1.2B-Thinking-Q4_0.gguf` and benchmarking script exists.

## Proposed architecture

### 1) Local model API (always in RAM)

- New Python service: `scripts/lfm25_local_api.py`
- Loads GGUF once on startup via `llama_cpp.Llama`.
- Exposes:
  - `GET /health`
  - `POST /v1/chat/completions` (OpenAI-like minimal format)
- Concurrency control:
  - `asyncio.Semaphore(MAX_CONCURRENCY)` guards inference calls.
  - Requests above the limit wait (bounded queue behavior from HTTP server).

### 2) Night planning in C#

- New C# neural decision engine in bots runtime.
- At session start, bot checks if a plan exists for local date:
  - If yes: reuse.
  - If no and local time is in configured night window: generate via model.
  - If no and outside night window: generate fallback deterministic plan and continue.
- Plan persisted per bot/day in SQLite (`BotNightPlans`).

Plan decides high-level behavior knobs:

- transfer: bid aggression, bid enable/disable, sell intent, desired profile
- scouting: enabled + intensity
- training: individual training slots + youth bias
- social/chat: tone + coordination style

### 3) Group chat channel per group

- New SQLite table `BotGroupChatMessages` scoped by `GroupId`.
- Transfer behavior writes "wanted players" messages to group chat every session when candidates exist.
- Message text is generated by model prompt (fallback to deterministic template on error).
- Optional mirrored global message with `[Group X]` prefix via API chat endpoint.

### 4) Real-time decisions in C#

- Existing behavior modules remain action executors.
- They consume `BotNightPlan` and group chat context.
- All API calls remain through translator client (`ExecuteForBotAsync`).

## Prompt strategy

### Prompt A: Night Strategy Planner

System prompt intent:
- You are an operations planner for one football manager bot.
- Output strict JSON only, no markdown.
- Balance risk, resources, squad age/talent, and current standings.

User prompt context:
- Bot traits (activity/risk/youth/social)
- Resources snapshot
- Squad summary (age/talent/fitness/strength buckets)
- Transfer market snapshot
- Ladder snapshot
- Group context

Output JSON schema:
- `shouldBid` (bool)
- `bidAggression` (0-100)
- `considerSelling` (bool)
- `scoutEnabled` (bool)
- `scoutIntensity` (0-100)
- `individualTrainingSlots` (0-3)
- `chatTone` (`supportive|neutral|competitive`)
- `coordinationLevel` (0-100)
- `transferTargetProfile` (short string)

### Prompt B: Group Transfer Intent Chat

System prompt intent:
- Produce a short team-group transfer message.
- Mention top targets, budget posture, and avoid spammy style.
- One concise line; no markdown.

User prompt context:
- Group id, bot identity, night plan summary
- top transfer candidates
- recent group chat messages

Output:
- plain text message <= 220 chars.

### Prompt C: Night Reflection (optional extension)

- Runs after session to compare plan vs actions/outcomes.
- Suggests next-night adjustment signals (stored as metadata).

## Operational constraints

- Neural API host default: `http://127.0.0.1:5057`
- Bot-side max concurrent model requests default: 4
- Request timeout default: 20s
- Hard fallback path if model/API fails: deterministic C# defaults

## Rollout plan

1. Add local model API service and startup docs.
2. Add DB schema for `BotNightPlans` and `BotGroupChatMessages`.
3. Add C# neural engine + prompt catalog + robust fallback parsing.
4. Integrate night plan into bot runner and decision-heavy behaviors.
5. Integrate group transfer intent messages.
6. Validate by building `bots/GoalTacticsBots.csproj` and smoke-running with a small bot count.
